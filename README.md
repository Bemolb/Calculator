# Пояснительная записка к тестовому заданию  

## 1. Общее описание решения

Реализовано приложение-калькулятор, поддерживающее **только операцию сложения**.  
Приложение сохраняет состояние между сессиями (текущий ввод + история вычислений) и корректно обрабатывает ошибки.

Проект выполнен с использованием **Clean Architecture** и шаблона **MVP**, разбит на **5 отдельных Assembly Definition** (модулей).

---

## 2. Архитектура проекта
Assets/
├── Calculator/
│   ├── Domain/                  → Calculator.Domain.asmdef
│   ├── Application/             → Calculator.Application.asmdef
│   ├── Infrastructure/          → Calculator.Infrastructure.asmdef
│   └── Presentation/            → Calculator.Presentation.asmdef
└── UI/
    └── Dialog/                  → UI.Dialog.asmdef

**Слои:**
- **Domain** — бизнес-правила, парсер, интерфейсы репозитория.
- **Application** — Use Case (`CalculateUseCase`), DTO `CalculationResult`.
- **Infrastructure** — реализация сохранения (`PlayerPrefs` + JSON).
- **Presentation** — MVP (View + Presenter).
- **UI.Dialog** — отдельный модуль диалоговых окон.

---

## 3. Соответствие требованиям ТЗ

| Требование ТЗ                               | Реализация                         
|---------------------------------------------|-------------------------------------
| Только сложение                             | `CalculatorParser` + regex
| Валидация ввода (примеры из ТЗ)             | Строгий regex + `long.TryParse`
| Вывод «ERROR» + диалог при ошибке           | `CalculationResult.Error` + `ErrorDialogService`
| Восстановление ввода после закрытия диалога | `OnDialogClosed` → `RestoreLastInput`
| Сохранение состояния между сессиями         | `ICalculatorRepository` + PlayerPrefs
| Clean Architecture                          | 5 слоёв + правильные зависимости
| MVP                                         | `ICalculatorView` + `CalculatorPresenter`
| Модули как отдельные assembly               | 5 `.asmdef` файлов

---

## 4. Реализованные особенности (сверх обязательных)

- Динамическое изменение высоты главной панели при росте истории.
- Автоматический скролл истории вверх.
- Защита от переполнения `long` (`checked` + `OverflowException`).

## 5. Предложения по дальнейшему улучшению

Хотя тестовое задание выполнено в полном объёме, ниже приведены улучшения, которые я могут быть реализованны:

### 5.1. Dependency Injection
**Предложение:** Внедрить VContainer (или Zenject).  
**Почему не сделано в тестовом:**  
ТЗ не требовало DI, а введение контейнера усложнило и увеличило бы проект. В рамках тестового достаточно ручного Composition Root (`CalculatorBootstrap`).

### 5.2. Вынос конфигурационных параметров
**Предложение:** 
- Regex-паттерн вынести в `const string` → `ScriptableObject CalculatorSettings`.
- Максимальную высоту панели, ключ PlayerPrefs, текста сообщений — в настройки.

**Почему не сделано:**  
ТЗ подчёркивает «сделать нужно так, как получается проще всего». Вынос в SO увеличил бы количество файлов и усложнил понимание базовой логики.

### 5.3. Unit-тесты
**Предложение:** Добавить тесты на `CalculatorParser.TryCalculate` и `CalculateUseCase` (NUnit).

**Почему не сделано:**  
ТЗ не требовало тестов. Основной акцент — на архитектуре и соответствии сценарию использования.

### 5.4. Дополнительно
- Лимит истории (чтобы не раздувать PlayerPrefs).
- Логирование через `ILogger`.

Все перечисленные улучшения — это следующий логичный этап развития проекта.

## 6. Как запустить

1. Открыть проект в Unity 6.3 (LTS).
2. Открыть сцену `Assets/Scenes/CalculatorScene.unity`.
3. Нажать Play.
